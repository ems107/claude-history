# Verifying a change

**Load this when:** you have changed something and need to prove it works, or you need a fixture with a particular property.

There is no automated test suite — this is a personal tool and the data it reads is real. Everything is verified against `~/.claude` itself, which makes the fixtures the fragile part: see below before trusting an id.

The checks keep their historical numbers; other documents link to them by number.

## Fixtures

Fixtures are sessions in `~/.claude/projects`, and Claude Code sweeps them on `cleanupPeriodDays` ([AI_TRANSCRIPTS.md](AI_TRANSCRIPTS.md#everything-here-has-an-expiry-date-cleanupperioddays)). When one is missing, **find a replacement by the property it was chosen for rather than dropping the check**, and say in the commit which fixture you used.

### Finding a replacement

Shortlist with ripgrep over `~/.claude/projects/*/*.jsonl`, then confirm by parsing — a grep also hits sessions that merely *discuss* the field, and this repo's own transcripts are full of those:

```
rg -l '"forkedFrom"'          # forks
rg -c '"compact_boundary"'    # compactions
rg -c '"queued_command"'      # queued lines (prompts AND notifications)
rg -c 'task-notification'     # notifications (noisy — confirm by origin.kind)
ls */*/subagents/*.jsonl      # sessions with agents
```

Duplicate uuids (replays) and branching parents (rewinds) need a real parse: read each line, count `uuid` seen twice and `parentUuid` values with more than one child.

## Two rules for any check that runs Claude

Checks 8, 19 and 23 spawn real `claude` processes against the user's subscription.

1. **Use `haiku` or `sonnet`, never `opus` or `fable`, and `low` effort.** None of these checks measures intelligence — they measure that the channel, the transcript, the indicator and the process cleanup work.
2. **Never kill processes by filtering on `claude.exe`**, by name or by command line. The agent running the test is one of them, and `taskkill /T /F` over a filter takes it out along with the target. **Capture the pid you spawned and kill that one, or kill nothing.** (This cost a session to learn.)

## Search

**3.** Search a Spanish phrase with and without accents → the same hits.

**9. Search, deep search, paging and marking.**

- `is invalid according` must find a phrase sitting across a newline in a pasted log, and the same query in NFD must match as in NFC. `is invalid` in words mode drops from 31 sessions to 12 with **Whole words only** (`is` inside `asistente`). A query of only accents, or of single letters, must answer 0 in ~0 ms and never spin.
- **Deep search**: a string existing only in a `tool_use` input (`old_string`) gives 0 normally and ~35 sessions in ~4 s deep; one only in tool output (`TS2339`) gives 0 then 1; a prose word plus a tool-only word in session scope gives 0 then a hit — that pairing is why the scan re-matches the indexed text. Cancel it mid-scan (`curl --max-time 1`) and the log must read `deep search cancelled` with the bytes it got through, not the full corpus.
- **Paging is arithmetic**, so check it without the browser: page `/api/search/session/:id/matches` to the end and the pages' `pageMatches` must sum to `matchCount` and their snippets to `total`, with `matchCount` equal to what `/api/search` said (`compact` → 46/46 in 38 places). Repeat with `deep=1` on a hit only the deep scan produces (`old_string` → 503/503 in 502 places for `f3384d17`, 6 pages of 100, ~16 MB re-read each, with `call`/`tool`/`agent` rows among them) — and page that same hit WITHOUT the flag to see it come back short, which is why the flag is threaded from the response into the request. `offset` past the end must answer 0 snippets with the totals intact, `limit=999` must clamp to 200, and every mode must behave the same way (words + session scope, whole words, and `in=user`, whose rows must all read USER).
- **Opening a result**: every snippet link with an anchor must carry `hl` (one per term, folded — an accented query gives `hl=sesion`) plus `hlw=1` when whole words are on, and none may carry an anchor without them.
- **`matchSpans` needs no browser**: feed it the pieces a markdown sentence breaks into and every span must cut out exactly the matched text — a phrase across three text nodes, one across a newline (`is invalid\naccording`), a haystack in NFD against a folded needle, `is` under whole-words, and the cap keeping the FIRST marks.
- **The rest needs a real browser**, and Chrome over the DevTools protocol does it with no dependency at all (Node has `WebSocket`): navigate to the link, and `[data-bubble].match-flash` must exist, `CSS.highlights.get('search-match')` must hold ranges whose `toString()` is the term, the first of them must be inside the viewport even when the bubble's top is hundreds of pixels above it (verified: top −647 on a 46-match session), and 9 s later both must be gone on their own. **A `<mark>` in the DOM means somebody went back to mutating React's markdown.**
- **Tool hits** are the same check against `[data-tool-id="<toolUseId>"]`, and there are four cases: a `call` (`old_string` → an `Edit`, marked inside the input JSON); a `tool` result read inline (`TS2339` → a `Read`); a call inside a COMPACTED segment (`toolu_01CkCY9SSEF…` in `432b1d41`, whose whole segment is folded on arrival — and only 4 tool blocks may be in the DOM afterwards, out of 210, or something opened the session instead of the run); and one whose output was OFFLOADED (`toolu_01LnH4KFDcZ…` in `4a1483ba`, `NOTION_TOKEN`, which exists only in the 90 KB file: no "Load full output" button may be left, and the marks must be inside the loaded text with the pre scrolled to the first one).
- **Session ids**: `797db462` must hit `797db462-4f17-…` with an `id` row carrying the whole uuid and a link with **no anchor**, alongside the sessions whose prose mentions it (4 hits here) — and the same for a session named nowhere (`5f6fa047` → 1 hit, 1 row), for the full uuid and for a 6-character prefix. `in=user` must drop the row; a word made only of hex letters (`cada`, `deba`, `add`) must produce none at all. Deep must stay a superset (`5f6fa047` deep → the id hit is still there) and its paging must still close: `deep=1` on `980751cb` gives 245 in 2 pages, 200 + 45, with the `id` row counted once. The empty-session case is what the header line is for: `?q=e1eb30cf` reads `0 matches in 0 sessions · 1 more hidden by the filters`, and `&empty=1` turns it into the hit.

## Cost and context

**10. Per-response cost — the pills must reconcile**, and that is checkable without the UI: sum `usage` over every assistant item of `GET /api/sessions/:id` at the `/api/prices` rates and it must equal the token panel's total to the last decimal (verified: delta 0 on 89- and 831-message sessions).

- On a fork it reconciles in **two halves**: items with `carriedOver: false` add up to `enrichment.usage`, items with `carriedOver: true` to `enrichment.carriedOverUsage`, exactly. (Verified on `c0f70eda` and, with an empty second half, on `0f5b1c8b` — both since swept; see the fixture table.)
- In the viewer, open a turn with a long tool run: the collapsed run carries its own pill (over half the spend lives there), expanding moves one pill onto the first call of each message, and the three levels must never show the same message twice.
- A session using `claude-haiku-4-5-20251001` must price at the `claude-haiku-4-5` rates — not "—" and never $0.000; a model with no row anywhere must read "—" and appear in the price editor in amber so it can be given one.

Re-cached context.** The arithmetic is checkable without a browser and must be, because three readers have to agree: drive the real `buildContextIndex` + `summariseRecache` over `/api/sessions/:id`, and for every session the viewer's `recachedTotal`, the sum of its per-turn `recached` and the sum of `enrichment.daily[*].recachedByModel` must be **identical** — 13,583,099 tokens and 56 events by all three paths across 108 sessions, zero mismatches. ## The viewer's own machinery

**18. The working indicator** needs a session that is genuinely busy, so run the check from inside a live Claude Code turn: `/api/live` must carry `status: "busy"` and a `statusUpdatedAt` matching the turn's start, and the session page must hold one `[data-bubble="assistant"]` reading `Claude is working… <counter>`, with the counter advancing by exactly the seconds waited. Any session that is not live must have none.

> The trap that will otherwise waste an hour: **headless Chrome reports `prefers-reduced-motion: reduce`**, so the reduced branch is what runs by default and `getAnimations()` says nothing about the real one. Emulate a real user first — `Emulation.setEmulatedMedia` with `prefers-reduced-motion: no-preference`.

**Both branches must move**, and the measurement is the computed `transform` / `opacity` sampled every 150 ms, not the presence of an animation. Normally the dots rise to −4.8 px, scale 0.85→1.14 and breathe 0.3→0.98 out of phase with each other, while `working-shimmer` walks the label's `background-position` (112% → 20% over the samples) with `-webkit-text-fill-color: transparent`. Under `reduce` there must be **no rise and no scale at all** (y = 0, s = 1) but the opacity must still travel 0.36→0.9 staggered, with the label back to a solid `--text-dim` and `animation: none`. A frozen indicator in either branch is a bug — it says "nothing is happening" while something is. Read the transform as text: `new DOMMatrix(getComputedStyle(el).transform)` throws on a computed `none` instead of giving identity, which silently reads as "the indicator is not there".

**21. - `20a73271` (DistribVB6_0) is the fixture for the rest: 26 links in one session, with `ActualizadorVersion/frmActualizador.frm` at 1,086 lines and `Actualizacion Base de Datos 2.0/sentenciasSQL.bas` at 376 KB, so one exercises the stripe and the other the "syntax highlighting skipped" note.

## Running Claude

**8. Auto-reload.** Point it at a throwaway folder and drive the config errors through `PUT /api/settings` (missing folder, a file instead of a folder, relative path, empty message, unknown model → each must come back in `configError`).

- "Send it now" must answer in a few seconds and log the reply, then flip to "started a window" on its own about a minute later without touching the page. The useful part cannot be scheduled, so read the log viewer (source `auto-reload`) afterwards.
- Press it twice in a row: the second press must be refused **with the reason next to the button** ("a message is being sent right now"), and pressing it again straight after the first finished must go through — no wait may ever leave it disabled and silent. Every refusal is logged too, so `"Send it now" refused` answers "I pressed it and nothing happened".
- **The no-floor rule is checkable without waiting five hours**: press "Send it now" while a window is running, and the log must read `the window was already running, so a reload is still due at its expiry` (the panel must *not* say "started a window"), with `nextCheckAt` landing on that expiry + 1 min — never on the send + 30 min.
- Toggle `autoReloadHideSessions` against a folder that HAS sessions and watch `/api/sessions`, `/api/projects`, `/api/prompts` and `/api/search` all drop together and come back.

**19. Sending a prompt from the app.** The two rules above apply first. Make a throwaway session (`claude -p "Reply with exactly: FIRST" --model haiku --output-format json` in a temp folder gives you its id), then drive the API with curl:

The log (source `chat`) tells the whole story and is the fastest way to read it. Note that `--resume` does NOT stamp a different `session_id` on the new lines, so the app shows no "resumed ×N" for these.
- The browser half needs no dependency: drive headless Chrome over CDP and check that the composer renders, that typing and clicking Send lights `[role="status"]`, that the answer text appears in the page, that the `[data-bubble]` count grows, and that the indicator goes out on its own.

Ask for `AskUserQuestion` outright ("pregúntame si prefiero rojo o azul"): the dialog must appear with Claude's own options, `Answer` must be disabled until one is picked, and answering must close it and let the turn finish. - The packaging half of the same story: `pnpm package`, extract the zip, run `versions\vdev\node\node.exe versions\vdev\server.cjs --port 7434` and it must index and answer — that is where a missing `import.meta.url` shim would surface, before any user sees it.

- **The collision guard needs a real terminal**, because `cmd /c start` minimized never gets far enough to register a session (verified: the process exists, `~/.claude/sessions` gains nothing). The cheapest fixture is the terminal you are already working in: your own session is open in one, so `GET /api/sessions/<your-own-id>/chat` must carry the block and a POST there must 409 (verified — `entrypoint: "cli"`, `status: "busy"`, against the composer's `sdk-cli` with no status at all). ## Platform and plumbing

**6. Installer.** `pnpm build && pnpm package -- --version 0.0.1`, extract the zip to a temp folder, run `install.ps1` (stop any dev instance first — same port), verify the task in `taskschd.msc`, check `Stop-ScheduledTask` frees port 7433 within ~5 s (parent-watchdog), `launch.vbs` cold-starts it, and `uninstall.ps1` removes task + shortcut while keeping `%LOCALAPPDATA%` data.

**7. Update, end to end.** Needs two published releases: install the older, wait ≤10 min (or "Check now") for the badge, apply, and check `update.log` plus the `versions\` pruning. Afterwards **the daily log must tell the whole story on its own** — filter it by `updates,update-helper` and you should be able to read the click, every download attempt, the checksum, the tar exit code, the helper registration, the junction swap, the health check and the result, in order and with no gap where the server exited.

The parts that need no release:

- the resumable download against a local HTTP server that drops the first attempt mid-body (it must resume with `Range` and end byte-identical);
- `updateLogImport` against a hand-written `update.log` (levels, original timestamps, and a second pass importing nothing). **Write that file the way the helper does** — run its `Log()` under `powershell.exe`, **not** pwsh (5.1 is what target machines have), against a root containing `ñ`, then check the first bytes are not `ef bb bf` and that the imported records still carry the `ñ`. Call `initLogging` at a temp dir first, or the test's own fake update-helper lines land in the real daily log.

**13. Executable resolution**, which cannot be checked from this machine's own profile (`Edgar` is ASCII, and a pwsh console hides the bug anyway): put a copy of any exe named `claude.exe` in a folder under a path containing `ñ`, point `process.env.PATH` at it and call `findClaudeCli()` — the returned string must be **identical** to the real path (no `�`) and must `spawn` without ENOENT. **14. Logs.** `/api/logs/day/<today>` with `level=`, `src=` and `q=` must each narrow the total; `2026-8-1` and a traversal attempt must both 400. Fastify wiring cannot be checked without a 500 — add a throwing route temporarily, confirm an `http` error record with the stack, and remove it.

**15. Retention.** **Never edit the real `~/.claude/settings.json` to test it.** Run a second server on a fake data root (`--data-root <tmp> --port 7434 --logs-dir <tmp>`, and set `CLAUDE_HISTORY_CACHE` too or the fake sessions land in the real cache) holding three transcripts whose mtimes you set to now / −10 d / −100 d. Then rewrite its `settings.json` between calls **without restarting** — the endpoint re-reads the files, and that is the whole contract behind the Refresh button:

- no key → `days: 30, usedDefault: true`;
- `7` → the −10 d and −100 d ones expired;
- `0` and `"30"` → `invalidValue` plus `sweepBlocked`, with `days` NOT presented as what applies;
- a truncated file → `sweepBlocked` carrying the parser's own message.

A `.claude/settings.local.json` in the fake project's folder must show up in `projectOverrides` with the project's name, and a broken `.claude/settings.json` beside it must appear too rather than being skipped. On the real root, `lastSweepAt` must track the **mtime** of `.last-cleanup`, not the ISO string inside it (they differ — Claude Code rewrites the file at each sweep).
